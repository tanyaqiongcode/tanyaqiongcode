# 一套写作/翻译质量规范的 LLM 盲测验证：六轮迭代、预注册阈值与判分口径工程

> 本文是 `cohesion-writing-translation`（私有技能仓库）评测工作的方法论公开版。
> 语料包与原始评测记录含出版物节选，保留在私有仓库；本文只公开方法、口径与结果数字。

## 要解决的问题

我维护一个面向 AI 辅助写作与翻译的衔接质量规范（SKILL.md：七检查点 + 机检清单 + 判例库）。规范本身"看起来有用"不构成证据——LLM 对自己的产出普遍偏乐观，同模型自埋错自检查的验证（命中 7/7）说服力不足。要回答的问题是：

**这条规范在未见过的文本上、由未参与开发的模型执行时，能不能稳定找出该找的问题、不制造噪音？**

## 方法：预注册 → 盲测 → 迭代 → 冻结

### 1. 预注册判定阈值（先写死，再跑测）

- **召回率 ≥ 80%**（埋错点命中数 / 埋错总数）
- **误报率 < 10%**（干净段上的旗标数 / 语料总句数）
- 未过线 → 漏报按检查点聚类、误报按"反复误报的规则须改写或加适用条件"的三分法处理，修订后再测

### 2. 盲测语料包设计

- 每轮一个语料包：**干净段 ~10 段（英语母语作者、经编辑的出版物原文）+ 埋错段 ~10 段（按检查点预埋、覆盖此前修过的漏报类型）**，混排后**去除"干净/埋错"标签与顺序信息**；中译英方向另设 B 部分（工作译稿 + 埋点）
- 语料制备本身也是审查对象：第一轮评审揪出 6 项缺陷（无效埋点、埋点制造病句、转写伪影污染）与 1 处同页重叠泄露，全部修复后才准跑测
- 埋点结构跨轮保持可比：每轮每检查点 ≥1 处，另设"未埋错对照段"

### 3. 执行隔离

- 检查者 = **全新会话**，只加载 SKILL.md + materials，**不可见 answer-key / 混排表 / 语料源文件**
- 模型无法可靠自报身份（第一轮后实测确认）——协议改为**由跑测人在存档头部记录模型、版本、深度思考开关**，不再要求模型自报
- 多模型并测：GPT、Gemini、豆包、DeepSeek（第五、六轮含 Claude 判分与桌面应用环境，口径上与前四轮只能近似比较，结果表中已注明）

### 4. 判分口径工程（三轮收紧）

| 轮次 | 命中标准 |
|---|---|
| 一~二 | 片段包含埋点改动处 |
| 三 | 上述 + 理由须与埋点对得上 |
| 四起 | **理由必须针对埋点改动本身**——检查点号相符但理由指向同句其他成分的不计 |

误报同样分级：只有"判错级"旗标计入误报率；译稿的忠实度旗标（误译/漏译）单独计召回、不与衔接误报混算。计分口径一旦改动，在验证矩阵中逐格标注，跨轮数字不直接混比。

### 5. 冻结与发布门槛

v1.0 的完成标准：判定阈值连续满足、**SKILL.md / 计分口径 / materials 指令连续两轮不改**（冻结用 git diff 逐字核验）、通过整章真实试用（第 2 章试用的产出直接用于改稿：有效 12 条 / 可选 17 / 无效 3 / 有害 0）。四条满足后才打 v1.0.0。

## 结果：六轮 × 四模型

| 轮次 | 版本 | GPT | Gemini | 豆包 | DeepSeek |
|---|---|---|---|---|---|
| 一 | v0.2.6 | 未通过（召回 56%） | 未通过（33%） | 未通过（33%） | 未通过（33%） |
| 二 | v0.2.7 | **通过**（100%） | 未通过（30%） | 未通过（40%） | **通过**（90%） |
| 三 | v0.2.8 | **通过**（A 80% / B 75%） | · | · | **通过**（A 80% / B 87.5%） |
| 四 | v0.2.9 | **通过**（A 80% / B 100%） | · | · | **通过**（A 80% / B 75%） |
| 五 | v0.3.0 | **通过**（A 80% / B 100%） | 未通过（A 60% / B 50%） | 未通过（A 60% / B 62.5%） | **通过**（A 100% / B 87.5%） |
| 六 | v0.3.0（冻结确认） | **通过**（A 100% / B 100%） | 未通过（A 60% / B 37.5%） | 平台拒答 | **通过**（A 100% / B 87.5%） |

- 第一轮**四模型全部不过线**——这正是盲测的价值：同模型自检时 7/7 命中，换了执行者召回只剩 33–56%
- 漏报聚类（连接关系误标、同类人物代词歧义、并列时态）直接驱动了 v0.2.7 的规则修订，第二轮召回整体抬升
- 判错级误报六轮全部 <10%（最高 6.1%，第二轮起 ≤0.8%）
- 部分规则表现出**模型依赖性**（如"两个同类人物后的代词"在 GPT/DeepSeek 上稳定命中、在 Gemini/豆包上不生效），按增强项而非通用规则处理
- 最终 GPT、DeepSeek 在第五、六轮连续通过且期间规则未改，满足冻结标准；v1.0.0 发布

## 诚实边界

- **样本量小**：A 部分每轮 5–9 个有效埋点，召回 80% 只差一两个旗标，未做置信区间
- **裁判与开发同源**：判分由我（借助模型）对照 answer-key 完成，未做裁判间一致性（κ）
- **C 轨人工盲评基线未做**：同批段落有/无规范的成对人工盲评仍是待办；有/无技能对照目前只有同模型版本（ab-test/）
- **运行环境不完全可比**：第五、六轮为桌面应用/Harness 环境，与前四轮网页版只能近似比较
- **v1.0.1 / v1.1.0 未回归**：后续修订的条目尚未进盲测，验证矩阵已明确标注适用版本

## 这个项目展示了什么

一套对 LLM 输出的**规范类**干预（prompt/规则/清单）如何做可信评测：预注册阈值防止"跑完再定标准"、混排盲测防止同模型自评的乐观偏差、口径逐轮收紧并留痕防止判分漂移、冻结 + 回归防止"改了不验"。完整产物包括：预注册评测计划、六轮语料包与协议、answer-key 与混排表、六份结果存档、按规则×模型×轮次的验证矩阵、有/无技能对照实验、整章试用报告。
